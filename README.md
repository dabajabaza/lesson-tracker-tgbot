# LessonTracker42Bot

Telegram-бот учёта оплат учеников преподавателя английского языка.
Работает на **Telegram Serverless** — код исполняется на инфраструктуре Telegram,
свой сервер не нужен, данные хранятся во встроенной SQLite-базе бота.

## Возможности

- Список учеников inline-кнопками со статусом оплаты: 🟢 ≥3 занятий, 🟡 2, 🟠 1, 🔴 0 (или долг).
- Карточка ученика: остаток занятий, денежный остаток, последняя оплата.
- Внесение оплаты: сумма + прежний денежный остаток → целые занятия, сдача сохраняется
  и учитывается при следующей оплате (цена 1600, оплата 6500 → +4 занятия и 100 ₽ остатка).
- Списание / возврат урока в одно нажатие (баланс может уйти в минус — это долг).
- Изменение стоимости занятия (только для будущих оплат).
- Бессрочная история операций по каждому ученику.
- Отмена последнего действия (стек: повторное нажатие откатывает предыдущее).
- Поиск по имени, сортировки (по имени / по остатку / «скоро оплата»).
- Экспорт учеников и истории в CSV текстом в чат (отправка .xlsx/файлов появится,
  когда Telegram Serverless разрешит загрузку файлов из обработчиков).
- Мультитенантность: ботом может пользоваться любое число преподавателей —
  у каждого пользователя Telegram свой изолированный набор учеников и история,
  все запросы фильтруются по `owner_id`. Ограничить круг пользователей можно
  штатно через BotFather: Bot Settings → «Restrict bot usage».

## Структура

```
schema.js                 — таблицы: students, operations, sessions, settings
handlers/message.js       — /start и текстовый ввод по FSM-состоянию
handlers/callback_query.js— все inline-кнопки
lib/students.js           — бизнес-логика (оплата, списание, отмена…)
lib/views.js              — экраны (меню, карточка, история, поиск)
lib/keyboards.js          — inline-клавиатуры и схема callback data
lib/render.js             — тексты, статусы, форматирование дат (МСК, UTC+3)
lib/money.js              — деньги в копейках: parse/format
lib/csv.js                — CSV и разбивка на сообщения ≤4096 символов
lib/session.js, lib/guard.js — FSM-состояния и проверка владельца
```

## Локальный запуск (пока Telegram Serverless в закрытой бете)

Доступ к Telegram Serverless раздаётся ограниченно ([t.me/devs/199669](https://t.me/devs/199669)).
До его появления бот работает локально на том же коде: папка `local/` содержит
адаптер `sdk` (Bot API по HTTPS + query builder на встроенном в Node.js SQLite)
и long-polling-раннер.

```bash
# API-токен бота (из @BotFather → API Token) — в файл .bot-token в корне
npm run local
```

Если прямой доступ к api.telegram.org заблокирован провайдером (fetch падает
с UND_ERR_CONNECT_TIMEOUT, а этой сети это свойственно) — запускать через
локальный прокси:

```bash
NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:1080 npm run local
```

База — `local/data.sqlite`. Токен ищется в `BOT_TOKEN` или файле `.bot-token`
(оба в .gitignore).

## Развёртывание в Telegram Serverless (когда откроют доступ)

1. В [@BotFather](https://t.me/BotFather): `/newbot` → имя `LessonTracker`,
   username `LessonTracker42Bot`.
2. Там же включить Serverless: `/mybots` → выбрать бота → кнопка **Serverless**
   (если кнопки нет — обновите Telegram и/или загляните в **Bot Settings**;
   опция появляется в свежих версиях BotFather). Затем **Serverless → CLI Access →
   Access token** — скопировать токен вида `app<id>:<secret>`
   (это отдельный токен, не совпадает с API-токеном бота).
3. В каталоге проекта:
   ```bash
   npm install          # ставит @tgcloud/cli
   npx tgcloud login    # вставить CLI-токен
   npx tgcloud migrate  # создать таблицы
   npx tgcloud push     # задеплоить код
   ```
4. Написать боту `/start` со своего аккаунта — он закрепится как владелец.

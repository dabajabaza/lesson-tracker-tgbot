Техническое задание
Telegram-бот для учета оплат учеников преподавателя английского языка
1. Цель проекта

Разработать Telegram-бота для автоматизации учета оплат учеников, работающих по абонементной системе.

Бот должен полностью заменить ручной подсчет оплаченных занятий и хранение информации об оплатах.

2. Общая логика работы

Я — преподаватель английского языка, работаю на себя.

Ученики оплачивают занятия заранее по абонементной системе. Количество занятий в одном платеже может быть любым (например, 4, 6, 8 и т.д.).

У каждого ученика своя стоимость одного занятия.

После каждого проведенного урока одно оплаченной занятие списывается с баланса ученика.

Основной принцип хранения данных:

основная единица учета — количество оплаченных занятий;
деньги используются только для расчета количества оплаченных занятий и хранения финансовой истории;
если после расчета остается неполная сумма, она сохраняется как денежный остаток и автоматически учитывается при следующей оплате.
3. Данные ученика

Для каждого ученика необходимо хранить:

внутренний уникальный ID;
имя;
стоимость одного занятия;
количество оплаченных занятий;
денежный остаток (если имеется);
дату последней оплаты;
сумму последней оплаты;
историю всех операций.

ID используется только внутри системы. Все операции должны быть привязаны именно к нему, а не к имени ученика.

4. Главное меню

После открытия бота отображается список всех учеников.

Для каждого ученика отображается:

имя;
стоимость одного занятия;
количество оставшихся оплаченных занятий;
статус оплаты.

7. Обработка суммы, не кратной стоимости занятия

Если сумма оплаты не делится на стоимость занятия без остатка, бот не должен отклонять платеж.

Он должен:

рассчитать максимально возможное количество полностью оплаченных занятий;
сохранить оставшуюся сумму как денежный остаток;
автоматически использовать этот остаток при следующей оплате.
Пример

Стоимость занятия:

1600 ₽

Поступила оплата:

6500 ₽

Бот рассчитывает:

оплачено занятий — 4;
денежный остаток — 100 ₽.

Ответ:

При следующей оплате остаток автоматически участвует в расчете.

Например:

остаток = 100 ₽

новая оплата = 1500 ₽

бот считает:

100 + 1500 = 1600 ₽

Добавляется одно занятие.

Новый денежный остаток становится равен нулю.

записывает операцию в историю.

9. Возврат занятия

Если урок был отменен или списан ошибочно, пользователь нажимает кнопку:

«Вернуть урок»

После этого бот:

увеличивает баланс оплаченных занятий на один;
сохраняет запись в истории.
10. История операций

Для каждого ученика должна храниться полная история.

Каждая запись содержит:

дату;
время;
тип операции;
сумму (если была оплата);
изменение количества занятий;
денежный остаток после операции (при необходимости).

Пример:

История хранится бессрочно.

11. Добавление ученика

При нажатии кнопки «Добавить ученика» бот последовательно запрашивает:

имя ученика;
стоимость одного занятия.
Проверка имени

После ввода имени бот должен проверить, существует ли уже ученик с таким именем.

Проверка выполняется без учета регистра.

Например:

Елена
елена
ЕЛЕНА

считаются одним именем.

Если имя уже существует, бот выводит сообщение:

Только после ввода уникального имени бот переходит к запросу стоимости занятия.

12. Изменение стоимости занятия

Стоимость занятия можно изменить.

При изменении:

новая стоимость применяется только к будущим оплатам;
история предыдущих оплат остается неизменной;
уже оплаченные занятия не пересчитываются.
13. Статусы оплаты

Баланс должен отображаться цветовой индикацией.

🟢 — осталось 3 и более занятий.

🟡 — осталось 2 занятия.

🟠 — осталось 1 занятие.

🔴 — осталось 0 занятий.

Требуется новая оплата.

14. Поиск

Должен быть поиск ученика по имени.

15. Сортировка списка учеников

Необходимо предусмотреть сортировку:

по имени;
по количеству оставшихся оплаченных занятий;
по тем, кому скоро потребуется оплата.
16. Отмена последнего действия

Необходимо реализовать возможность отменить последнее действие.

Поддерживаемые операции:

внесение оплаты;
списание занятия;
возврат занятия;
изменение стоимости занятия.

После отмены данные должны полностью возвращаться к предыдущему состоянию.

Предусмотреть экспорт данных в:

Предпочтительный стек технологий:

Telegram Bot API;
Python;
aiogram (актуальная стабильная версия);

Все данные должны храниться в базе данных.

20. Требования к интерфейсу

Интерфейс должен быть максимально простым и интуитивно понятным.

Основные действия должны выполняться не более чем за 2–3 нажатия.

Использование текстовых команд должно быть минимальным.

Основной способ взаимодействия — кнопки.

21. Возможность дальнейшего расширения

Архитектура бота должна предусматривать возможность добавления новых функций без существенной переработки существующего кода.

Планируемые улучшения:

интеграция с календарем занятий;
автоматическое списание занятий по расписанию;
автоматические напоминания преподавателю о необходимости запросить оплату;
финансовая статистика (день, неделя, месяц, год);
архивирование неактивных учеников;
заметки по ученикам;
история изменения стоимости занятий;
поддержка разных типов занятий (индивидуальные, парные, групповые);
поддержка нескольких преподавателей.
Основной принцип работы

Главная задача бота — вести учет оплаченных занятий, а не денежных средств. Деньги используются только для расчета количества занятий, хранения истории оплат и учета денежных остатков, если сумма оплаты не кратна стоимости одного занятия. Интерфейс должен быть максимально быстрым и удобным, чтобы все ежедневные операции (оплата, списание урока, просмотр остатка) выполнялись буквально за несколько нажатий.
